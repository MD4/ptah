# Debug "Why is this light doing that" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the live Monitor, clicking a cell of `Going out` selects its light, and a panel says for that light, at each frame: who wrote each attribute, who won and why, what the overrides did, and where each channel value comes from.

**Architecture:** The engine watches at most one light. For it only, the render thread records into storage allocated at load: who wrote (identity the merge does not keep), the merge's own verdict per layer, the overrides' before/after, and the fixture step's per-channel source. The explanation is published like a debug frame, turned into ids by telemetry, and served on a new WebSocket topic `why`. The design system adds a pure wording model, cell selection and a panel; the web app wires selection, URL and the topic.

**Tech Stack:** Rust 1.93 (no new crate), React 19 + the ds, Vitest, Storybook gates, Playwright 1.59.1, Biome, cargo-nextest 0.9.150.

**Spec:** `docs/superpowers/specs/2026-11-18-v2-debug-why-design.md` (V1 repo, 53a4cfc). Executors read it first; § numbers below refer to it.

## Review Focus

1. A show or venue reload while a light is watched: the engine's fixture index changes or the fixture disappears; the panel must never explain another light. → Task 4 `a_load_clears_the_watch`, Task 5 `the_watch_is_set_again_after_a_load_when_the_fixture_remains`, `…and_cleared_when_it_is_gone`.
2. A busy frame on the watched light (a chase with more than 64 writes, a full merge slot): counted in `more`, no panic, no allocation, the winner still right. → Task 3 `more_than_64_writes_are_counted_not_lost_silently`, the allocation guard with a watch.
3. The panel explaining another frame than the grid shows. → Task 4 `the_explanation_carries_the_frame_index_of_the_debug_frame_sent_with_it`; Task 9 applies both in the same animation frame.
4. Two screens: one closes or its socket sleeps while the other still watches; the watch must stay; when the last leaves it must clear. → Task 5 `the_watch_outlives_one_of_two_subscribers`, `the_last_subscriber_leaving_clears_the_watch`.
5. Odd fixtures: one whose channels pass 512, 16-bit pairs, more than 64 channels, a light the engine did not resolve. → Task 2 source cases, Task 3 `a_fixture_past_512_explains_its_channels_inside_the_universe`, Task 4 refusals.

### Task 1: The merge says who won and why (vm)

**Files:**
- Modify: `crates/ptah-vm/src/merge.rs`, `docs/vm-rust.md`
- Test: `merge.rs` unit tests

**Interfaces:**
- Produces:
  ```rust
  #[derive(Clone, Copy, Debug, PartialEq, Eq)]
  pub enum Verdict { Only, Priority, Highest, Last,           // a winner's reason
                     LostPriority, Lower, Earlier, Legacy }   // a loser's reason
  #[derive(Clone, Copy, Debug, PartialEq)]
  pub struct LayerView { pub id: WriterId, pub start_seq: u64, pub route_order: u32, pub priority: f64,
                         pub mode: MergeMode, pub value: f64, pub won: bool, pub verdict: Verdict }
  impl MergeBuffer {
      /// The layers of (fixture, attr) in start order with the ranking's verdict; returns how many
      /// exist (may exceed `out.len()`; the winner is always among those written).
      pub fn explain(&self, fixture: u32, attr: Attribute, out: &mut [LayerView]) -> u32;
  }
  ```
- Rules: `resolve_ranked` and `explain` share one ranking (extract it; do not write the comparison twice). Exactly one layer has `won` when any exists. HTP (level, rate) tie at the top priority: the mark goes to the earliest started among those at the maximum value; `Highest` when several default layers share the top priority, `Priority` when the winner outranks at least one default layer and is alone at its priority, `Only` for a single layer, `Last` for LTP among equals and for a legacy winner among legacy layers. Losers: `LostPriority`, `Lower` (HTP), `Earlier` (LTP and legacy), `Legacy` (a legacy layer under any default layer). Priority `+∞` and `f64::MAX` writers are ranked as any other (the caller words them).
